# 単語レイド（試作）引き継ぎメモ

英単語タイピング × クラス協力バトルのWebアプリ試作。
このファイルと `index.html` を渡せば、別のClaude（または人）が続きから開発できるようにまとめています。

- 最終更新：2026-11-16
- ファイル構成：

| ファイル | 役割 |
|---|---|
| `index.html` | ゲーム本体（claude.ai 上ではこれ1つで動く） |
| `site-config.js` | 公開版の設定（Firebase の設定値、GA4 の測定ID） |
| `net-core.js` | クラス対戦の通信（Firebase版）。claude.ai の room と同じ使い方にそろえた部品 |
| `net-firebase.js` | Firebase に接続して `net-core.js` を index.html に渡す |
| `database.rules.json` | Firebase Realtime Database のアクセス制御ルール |
| `firebase.json` / `.firebaserc` | Firebase Hosting の公開設定（公開するファイル、セキュリティ用ヘッダー）とプロジェクト指定 |
| `analytics.js` | アクセス解析（GA4）。送る項目を限定 |

## 1. コンセプト

- 寿司打のような「流れる」系ではなく、**英単語で攻撃してモンスターを倒すレイドバトル**。
- 授業で使える **Kahoot風のクラス機能**：先生が部屋をつくり、生徒が6けたコードで参加、全員のダメージで1体のボスを削る協力戦＋個人ランキング。
- 終わったあとの **振り返り** と **先生向けCSV** を重視。

## 2. 遊び方（現在の仕様）

| 項目 | 内容 |
|---|---|
| 答え方 | 「英語→日本語」「日本語→英語」の2モード |
| 単語セット | 中学の基本（B01〜）、経済・ビジネス（E01〜）、TOEIC頻出（T01〜）、自分の単語（C01〜） |
| 制限時間 | 60 / 90 / 120 秒 |
| 1問の時間 | 約13秒（コンボで短くなり最短9秒） |
| ヒント | 1問の時間の65%が過ぎるとKahoot風の4択（▲◆●■、1〜4キー）が出る |
| ダメージ | 打って正解：100＋120×残り時間割合、コンボ倍率（最大2倍）。4択正解：半分・コンボ増えない |
| 失敗 | 時間切れ・4択ミス・Escでとばす → コンボリセット、まちがいとして記録 |
| ボスHP | 1200 × 参加人数 × (1 + 0.35 × 何体目) |
| ひとりモード | CPUの仲間3人（リン・ソウタ・ミオ）と協力 |
| 日本語入力 | IME確定で判定。ひらがな・カタカナも正規化して判定（意味の候補を `/` 区切りで複数登録） |

## 3. クラス機能

- 先生：「部屋をつくる」→ 6けたコード表示（使われていないコードを確保） → 「スタート」で全員同時開始。
- 先生画面：ボスHP、ダメージランキング、表彰台、**まちがえやすかった単語の表**、**生徒ごとの結果の表**。
- 先生が「自分の単語」を選んでいれば、その単語リスト（重み付き）を生徒全員に配信（最大およそ60語）。
- 途中参加は不可。

### 通信の仕組み（重要）

現在は **claude.ai のアーティファクト専用機能** を使っています。

- `claude.use("room")`：同じページを開いている人どうしのリアルタイム通信
  - `join("raid-<コード>")` で部屋に参加
  - 生徒は presence に `{role:"player", nick, dmg, combo, st, sum, state}` を載せる
    - `st`：`{ "<単語番号>": [出題回数, まちがい回数, 4択正解回数] }`
    - `sum`：`[打って正解, 4択正解, まちがい, 最大コンボ]`
  - 先生は presence `{role:"host"}`、トピック `start` で `{mode, deck, secs, epoch, words?}` を送信
- `claude.use("downloads")`：CSVの保存

**claude.ai 上**：上の room / downloads を使います（持ち主と同じ組織のメンバーか招待された人だけ参加可）。

**公開版（GitHub Pages など）**：`window.claude` がないときは、`net-firebase.js` が Firebase Realtime Database 版の通信部品を `roomNS` として渡します。
`pub()`・`party()`・`collect()`・参加／部屋作成／スタートの処理、ゲーム本体の関数はそのまま使っています。CSVはブラウザの通常のダウンロードで保存します（列・形式は同じ）。

Firebase 版のデータ構造：

| 場所 | 中身 | 読める人 | 書ける人 |
|---|---|---|---|
| `rooms/{コード}/meta` | 先生のID、作成時刻 | ログイン済みの全員 | 新規作成時と先生 |
| `rooms/{コード}/players/{ID}` | role, nick, dmg, combo, state | 部屋の全員 | 本人だけ |
| `rooms/{コード}/stats/{ID}` | st, sum | 先生だけ | 本人だけ |
| `rooms/{コード}/start` | スタートの合図 | 部屋の全員 | 先生だけ |

- ログインは Firebase の匿名ログイン（タブごとにランダムなID）。本名・メールアドレスは使わない。
- 参加コードは6けた。作成時にトランザクションで空きを確認し、作成から6時間たった部屋は空きとして再利用。
- 得点の不正対策（ルールで検証）：ダメージは減らない（0へのリセットのみ可）、1回の増加は1000まで、項目と型・範囲をチェック。ブラウザで計算するゲームなので完全な防止はできない。
- 生徒が画面を閉じると本人のデータを削除、先生が「部屋を閉じる」と部屋ごと削除。

## 4. 公開版のセットアップ

1. Firebase でプロジェクトを作成
2. 「Authentication」→ ログイン方法で「匿名」を有効にする
3. 「Realtime Database」を作成（ロケーションは近い地域）し、「ルール」に `database.rules.json` の中身を貼り付けて公開
4. プロジェクトの設定 → ウェブアプリを追加 → 表示される設定値を `site-config.js` の `firebase` に入れる（`databaseURL` も必要）
5. Google Analytics 4 を使う場合は、測定ID（G-…）を `site-config.js` の `gaId` に入れる
6. `privacy.html` の運営者名・連絡先を確認（記入済み）
7. 公開先を選ぶ
   - **GitHub Pages**：Settings → Pages で公開（Branch: `main`）
   - **Firebase Hosting**：`firebase.json` と `.firebaserc`（プロジェクト `tango-raid`）を同梱。リポジトリのフォルダで次を実行
     ```bash
     npx -y firebase-tools@latest login
     npx -y firebase-tools@latest deploy --only hosting,database
     ```
     公開URL：`https://<プロジェクトID>.web.app`（このドメインは Firebase 認証の承認済みドメインに自動で入る）
   - Webアプリの設定値は `npx -y firebase-tools@latest apps:sdkconfig WEB <アプリID>` で表示できる

設定が空のままでも、ひとりモードとCSV保存は動きます。

### 運用費の目安
- GitHub Pages：無料（公開リポジトリ）
- Firebase：無料プラン（Spark）は同時接続100まで（30人クラスなら同時に3クラス程度）。超える場合は従量課金（Blaze）へ
- GA4：無料

## 5. アクセス解析（GA4）

| イベント | 項目 | 用途 |
|---|---|---|
| （自動）page_view | — | PV、月間アクティブユーザー、継続利用率 |
| `game_start` | play（solo/class）, mode, deck, secs | ゲーム開始回数 |
| `room_create` | — | 対戦ルーム開催回数 |
| `room_start` | players, mode, deck, secs | 開始時の参加者数 |
| `room_join` | — | 参加者数 |

- ニックネーム、教室コード、点数、答えは送らない（`analytics.js` の ALLOW 以外は送信されない）。
- Googleシグナルと広告のパーソナライズは無効。`privacy.html` で利用者がブラウザごとに計測を止められる。
- 改正電気通信事業法の外部送信規律に対応するため、全ページのフッターから `privacy.html` にリンク。

## 6. CSV形式

### 単語CSV（読み込み用）
```
番号,英単語,意味
C01,revenue,収益/売上/しゅうえき
C02,profit,利益/りえき
```
- 番号は省略可（自動で C01〜 を付与）。
- 意味は `/` 区切りで複数正解。ひらがなでも正解にしたい場合はひらがなも並べる。
- 1行目に「英単語」を含む行はヘッダーとして読み飛ばす。

### 番号指定
`E01-E10, T03, T07` のように入力すると、その単語でセットを作る。

### 先生向け：単語別CSV（`単語別_<コード>_<日付>.csv`）
```
番号,英単語,意味,まちがえやすさ,まちがえた人数,答えた人数,まちがい回数,4択で正解,出題回数,まちがえた生徒
```
- まちがえやすさ ＝（まちがい＋4択×0.5）÷ 出題回数
- **このCSVを読み込み直すと、そのまま次回の問題になる**
  - まちがえやすさに応じて出題回数を最大4倍に重み付け（チェックで無効化可）
  - 「まちがえやすさ20/40/60%以上」で絞り込み可

### 先生向け：生徒別CSV（`生徒別_<コード>_<日付>.csv`）
```
名前,ダメージ,打って正解,4択で正解,まちがい・時間切れ,出題数,打って正解した割合,最大コンボ,まちがえた単語（番号）,まちがえた単語
```
- 問題としては読み込めない（読み込もうとすると案内メッセージを表示）。

### 生徒・ひとり用：まちがえた単語CSV
```
番号,英単語,意味,まちがえた回数
```
- 読み込み直すと、まちがえた回数に応じて重み付け出題。

## 7. コードの構成（index.html）

1つの `<script>` ブロック内、主な関数：

| 区分 | 関数 |
|---|---|
| 単語データ | `DECKS`、`ALL`（番号→単語のMap）、`parseCSV`、`setCustom`、`weighted` |
| ゲーム | `startGame`、`next`、`loop`、`openChoices`、`check`、`hit`、`fail`、`end`、`track` |
| パーティ/ボス | `party`、`boss`、`arena`、`refresh`、`rankHTML`、`podium` |
| クラス | `pub`、`valid`、`collect`、`classAgg`、`stuRows`、`renderAgg`、`renderStu`、`hostTick` |
| 出力 | `toCSV`、`aggCSV`、`stuCSV`、`save`、`copyOut` |
| 計測 | `metric`（`window.tangoMetric` に渡すだけ。ゲーム本体の関数には入れていない） |

単語1件は配列 `[英単語, "意味1|意味2|...", 番号]`、重みは配列のプロパティ `wt`。

## 8. 試作で見送ったこと・既知の課題

- 振り返りテストのPDF生成：いったん見送り（CSV中心に）。
- Firebase版の通信は、疑似データベースを使った「先生1人＋生徒2人」の通しテストで確認済み。本物の Firebase とルール（`database.rules.json`）での確認はまだ（Firebase コンソールの「ルールのプレイグラウンド」か Emulator で要確認）。
- 得点の厳密な検証（サーバー側での再計算）は未対応。Cloud Functions（有料プラン）が必要。
- 部屋が閉じられずに残ったデータ（先生のタブが突然閉じた場合の meta / start）は、次に同じコードが使われるときに上書きされる。定期削除は未対応。
- 日本語の意味の言い換え（登録外の表現）は不正解になる。
